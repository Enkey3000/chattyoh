# User Stories

**Project:** ChattyOh Inc · **Version:** 0.1 (draft) · **Owner:** Product Owner · **Status:** Draft
**Upstream:** `target-users.md`, `01-prd.md` · **Downstream:** `02-srs.md`, `09-uat-plan.md`, `08-test-cases.md`

Format: *As a [persona], I want [capability], so that [benefit].* Acceptance criteria use Given / When / Then in short form. Each story links to a PRD item and the SRS requirements it drives. `tools/rtm.py` warns when a functional requirement has no story.

Personas: **Maker** (P1), **Team lead** (P2), **Admin** (P3), **Agency lead** (P4). Roles in the product: Owner, Admin, Developer, Viewer.

| ID | Story | Acceptance criteria | PRD | SRS | Slice |
|---|---|---|---|---|---|

| US-002 | As an Admin, I want multi-factor sign-in and re-authentication for sensitive actions so that stolen sessions are less harmful | Given MFA is enabled, when I change a role or approve an agent deployment, then I must re-authenticate if my last sign-in is older than 5 minutes | PRD-F-01 | SRS-FR-AUTH-002 | MVP-1 |
| US-003 | As a user, I want to see and revoke my active sessions so that I can end access from a lost device | Given I have several sessions, when I revoke one, then that session stops working immediately | PRD-F-01 | SRS-FR-AUTH-003 | MVP-1 |
| US-004 | As a Team lead, I want a separate Team workspace so that work and data stay apart from my personal space | Given two workspaces, when I switch, then I see only that workspace's data | PRD-F-01 | SRS-FR-WS-001 | MVP-0 |

| US-006 | As an Admin, I want role changes recorded and Viewers kept read-only so that access is controlled | Given a Viewer, when they try to edit, then the action is refused; when I change a role, then an audit event is written | PRD-F-01 | SRS-FR-WS-002,SRS-FR-AUDIT-001 | MVP-1 |
